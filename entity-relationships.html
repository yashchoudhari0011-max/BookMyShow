BookMyShow Entity Relationship Map

A visual guide to the entities in your Spring Boot project

City→Theatre→Screen→Show→Booking

City

  • PK id
  • name
  • state

Theatre

  • PK id
  • name, address
  • FK city_id → City

Screen

  • PK id
  • name, totalSeats
  • FK theatre_id → Theatre

Seats

  • PK id
  • seatNumber, row, col
  • seatType
  • FK screen_id → Screen

Movie

  • PK id
  • title, genre, language
  • durationMinutes, rating
  • releaseDate, description

Shows

  • PK id
  • FK movie_id → Movie
  • FK screen_id → Screen
  • showDate, startTime, endTime
  • ticketPrice

User

  • PK id
  • name, email, password
  • phonenumber, createdAt

Booking

  • PK id
  • FK user_id → User
  • FK show_id → Shows
  • totalPrice, status, bookedAt

How to read the relationships

City 1 → many Theatres: one city can contain many theatres. Each theatre belongs to one city through city_id.
Theatre 1 → many Screens: a theatre can have multiple screens/auditoriums. Each screen belongs to one theatre through theatre_id.
Screen 1 → many Seats: every screen has many physical seats. Each seat belongs to one screen through screen_id.
Movie 1 → many Shows: one movie can be scheduled multiple times, so each show refers to one movie through movie_id.
Screen 1 → many Shows: a screen can host many shows at different times. Each show uses one screen through screen_id.
User 1 → many Bookings: a user can make many bookings. Each booking belongs to one user through user_id.
Show 1 → many Bookings: many users may book tickets for the same show. Each booking refers to one show through show_id.
Booking many ↔ many Seats: one booking may include several seats, and seats are connected through the join table booking_seats (booking_id, seat_id).

Interview explanation: “A movie is scheduled as a show on a particular screen. A user creates a booking for that show and selects one or more seats. The booking stores the final price, status, and booking time.”
